# Governance

The Kubescape workflows repository follows the
[Kubescape project governance](https://github.com/kubescape/project-governance/blob/main/GOVERNANCE.md).
That document is authoritative for project governance, including maintainer and
triager eligibility, appointment, and removal.

## Decision making

Propose changes in a public issue in this repository so the community can discuss
them and reach consensus before implementation. Submit agreed changes as pull
requests for maintainer review. Maintainers approve and merge changes, manage
releases, set project priorities, and ensure the quality and stability of the
workflows.

Triagers organize the issue and pull request backlog, apply labels and milestones,
assign reviewers, ask clarifying questions, and reproduce reported bugs. Triagers
do not merge pull requests; merging remains the responsibility of maintainers.

Anyone can participate through code, documentation, issue triage, discussions,
and feedback. See the central
[maintainer and triager list](https://github.com/kubescape/project-governance/blob/main/MAINTAINERS.md)
for the project teams.

## Conflict resolution and conduct

Participants should first try to resolve disagreements together. Unresolved
conflicts are escalated to the maintainers, whose decision is final under the
central governance policy. All project interactions must follow the
[Kubescape code of conduct](https://github.com/kubescape/project-governance/blob/main/CODE_OF_CONDUCT.md).

Proposed governance changes follow the issue discussion and pull request review
process described in the central governance document.
